# قواعد العمل (Business Rules)

## 1. المنتجات والظهور
| الإجراء | القاعدة |
|---|---|
| إضافة | ينشأ `draft`؛ يحتاج variant واحد على الأقل ليُفعَّل |
| تفعيل للمتجر | `status=active` + `is_visible_on_store=true` |
| تعطيل الظهور | `is_visible_on_store=false`: يختفي من الـ Storefront فوراً (ويُلغى cache) لكن يبقى في النظام والطلبيات القديمة |
| أرشفة | `status=archived`: لا يُباع ولا يظهر، يبقى للتقارير |
| حذف | soft delete فقط، **ممنوع** إن وُجدت حركات مخزون أو طلبيات (يُقترح الأرشفة) |
| SKU | فريد عالمياً، لا يُعاد استخدامه بعد الحذف |
- منتج بدون مخزون متاح (`track_inventory=true`): يظهر «غير متوفر» ولا يمكن إضافته للسلة (إلا إن سُمح بالطلب المسبق لاحقاً).

## 2. التسعير
- السعر من `ProductPrice` حسب `PriceList` لعملة الطلبية. إن لم يوجد سعر بعملة الطلب → خطأ (لا تحويل ضمني على سعر البيع في المرحلة الأولى).
- سعر السطر يُنسخ إلى `OrderLine` عند الإنشاء ولا يتغير بعدها.
- الضريبة: بحسب `TaxRate` للمنتج، وتُحسب على (السعر − الخصم). السعر غير شامل الضريبة افتراضياً.

## 3. المخزون
- `available = on_hand − reserved`.
- كل تغيير في الكميات = `StockMovement` + تحديث `StockLevel` في معاملة واحدة بقفل صف.
- ممنوع الرصيد السالب (CHECK).
- **الحجز:** عند تأكيد الطلبية (أو checkout للدفع المسبق) → `reserved += qty`. ينتهي بعد `expires_at` للطلبيات غير المدفوعة عبر management command دوري (cron).
- **الخصم الفعلي:** عند الشحن → `on_hand −= qty`, `reserved −= qty`, حركة `sale_out`.
- **الإلغاء:** قبل الشحن → تحرير الحجز. بعد الشحن → مرتجع.
- **التكلفة (Weighted Average):** عند كل استلام:
  `new_cost = (on_hand_total × old_cost + qty × unit_cost_base) / (on_hand_total + qty)`.
  `OrderLine.unit_cost` يلتقط التكلفة وقت الشحن.
- **الجرد:** يُدخل العدّ الفعلي → فرق → حركة `adjustment` + قيد.
- **التحويل بين المخازن:** `transfer_out` ثم `transfer_in` عند الاستلام (مخزون في الطريق اختياري).

## 4. دورة الطلبية
```
pending ──confirm──▶ confirmed ──process──▶ processing ──ship──▶ shipped ──deliver──▶ delivered
   │                    │                      │
   └──────cancel────────┴──────cancel──────────┘        shipped/delivered ──return──▶ returned (جزئي/كلي)
```
| الانتقال | الأثر |
|---|---|
| pending → confirmed | تحقق من التوفر، حجز المخزون، (قيد ذمم/مبيعات حسب السياسة) |
| confirmed → processing | تجهيز (لا أثر مالي) |
| processing → shipped | خصم المخزون، قيد تكلفة المبيعات، إصدار فاتورة إن لم تصدر |
| shipped → delivered | إغلاق التسليم؛ COD: تسجيل التحصيل |
| any → cancelled | تحرير الحجز؛ إن وُجد قيد أو دفعة → قيد عكسي/استرداد |
| → returned | `SalesReturn`: إعادة للمخزون (إن restock)، قيد عكسي، استرداد |
- الانتقالات خارج الجدول **مرفوضة**. كل انتقال يسجّل في `OrderStatusHistory`.
- `payment_status` مستقل عن `status` ويُحسب من مجموع الدفعات المكتملة.
- Idempotency: نفس `idempotency_key` يعيد نفس الطلبية.

## 5. متعدد العملات
- **العملة الأساسية** واحدة (`is_base`). كل مستند يحمل `currency` + `exchange_rate` وقت الإنشاء (لقطة).
- `amount_base = amount × rate`، تُخزَّن الأصلية والأساسية في `JournalLine`.
- سعر الصرف: آخر `ExchangeRate` ≤ تاريخ المستند؛ يمكن تحديده يدوياً على المستند.
- **فروقات الصرف المحققة (Realized):** عند الدفعة، إن اختلف سعر الصرف عن سعر الفاتورة يُسجَّل الفرق في «أرباح/خسائر فروقات صرف» ليتوازن القيد.
- **إعادة التقييم (Unrealized):** في نهاية الفترة، لأرصدة الذمم/الصناديق بعملة أجنبية (قيد تقييم يُعكس تلقائياً بداية الفترة التالية) — مرحلة M7.
- الأسعار والتقارير: تُعرض بالعملة الأساسية أو الأصلية.

## 6. القيود المحاسبية التلقائية
(أمثلة بالعملة الأساسية؛ كل قيد يُنشأ ويُرحَّل داخل نفس المعاملة)

| الحدث | مدين | دائن |
|---|---|---|
| شحن/فاتورة بيع آجل | ذمم العملاء (الإجمالي) | المبيعات (صافي) + ضريبة مستحقة |
| شحن/فاتورة (تكلفة) | تكلفة المبيعات | المخزون |
| دفعة زبون | الصندوق/البنك | ذمم العملاء (± فرق صرف) |
| بيع نقدي/دفع مسبق | الصندوق/البنك | المبيعات + ضريبة مستحقة |
| مرتجع مبيعات | مرتجعات المبيعات + ضريبة مستحقة | ذمم العملاء/الصندوق |
| مرتجع (تكلفة) | المخزون | تكلفة المبيعات |
| استلام مشتريات + فاتورة | المخزون + ضريبة مدفوعة | ذمم الموردين |
| دفعة مورد | ذمم الموردين (± فرق صرف) | الصندوق/البنك |
| جرد: زيادة | المخزون | فروقات جرد |
| جرد: نقص | فروقات جرد | المخزون |
| مصروف شحن مدفوع | مصروفات الشحن | الصندوق/ذمم |

**ربط الحسابات:** جدول إعدادات `AccountMapping` (مفتاح ← حساب): `sales`, `cogs`, `inventory`, `receivable`, `payable`, `cash`, `bank`, `tax_collected`, `tax_paid`, `inventory_adjustment`, `fx_gain`, `fx_loss`.

## 7. قواعد القيود
1. القيد لا يُرحَّل إلا إذا `SUM(debit) = SUM(credit)` وعدد أسطره ≥ 2.
2. السطر إما مدين أو دائن، والحساب `is_postable`.
3. لا ترحيل في فترة `closed`.
4. المرحَّل لا يُعدَّل ولا يُحذف؛ التصحيح بقيد عكسي (`reversal_of`) ثم قيد جديد.
5. القيد التلقائي يحمل `source_type/source_id` للرجوع للمستند.
6. القيود اليدوية تُنشأ `draft` وتُرحَّل بصلاحية المحاسب.

## 8. المشتريات
- أمر الشراء لا يؤثر على المخزون ولا الدفاتر. **الاستلام** هو الذي يُدخل المخزون ويحدّث التكلفة. الفاتورة تُنشئ الذمة.
- استلام جزئي مسموح (`partial`).

## 9. التقارير
ميزان المراجعة، دفتر الأستاذ، قائمة الدخل، الميزانية العمومية، كشف حساب عميل/مورد، أعمار الذمم، تقييم المخزون، حركة صنف، المبيعات حسب المنتج/الفترة، الربحية (من `unit_cost` snapshot).

## 10. الصلاحيات
الصلاحيات **ديناميكية** يديرها الأدمن (انظر `02-database-design.md`، قسم «نظام الصلاحيات»)، والجدول التالي مجرد **قوالب مبدئية** تُزرع كأدوار قابلة للتعديل:

| المورد | Admin | محاسب | أمين مخزن | مبيعات | زبون |
|---|---|---|---|---|---|
| المنتجات | كل شيء | عرض | إضافة/تعديل | عرض | عرض (الظاهر فقط) |
| المخزون | كل شيء | عرض | كل شيء (دون التكلفة) | عرض | — |
| الطلبيات | كل شيء | عرض | تجهيز/شحن | كل شيء (دون إلغاء بعد الشحن) | طلباته فقط |
| الدفعات | كل شيء | كل شيء | — | تسجيل | — |
| القيود/الحسابات | كل شيء | كل شيء | — | — | — |
| المشتريات | كل شيء | كل شيء | استلام | — | — |
| المستخدمون والصلاحيات | كل شيء | — | — | — | — |

**قواعد إدارة الصلاحيات:**
1. الأدمن فقط يمنح/يسحب الأدوار والصلاحيات (`users.manage_roles`, `users.manage_permissions`)، ولا يستطيع موظف منح صلاحية لا يملكها.
2. الموظف الجديد بلا أي صلاحية حتى يُمنح دوراً.
3. لا يمكن حذف آخر أدمن ولا سحب صلاحيته (حماية من القفل الذاتي).
4. تغيير صلاحيات موظف يسري فوراً (إبطال الكاش وإنهاء/تحديث توكناته).
5. كل منح أو سحب أو تعديل نطاق يُسجَّل في AuditLog (من، لمن، ماذا، متى، سبب).
